# 看板快照 · 数据契约

> 看板快照 JSON 是「Obsidian 单一事实源」与「微信小程序派生视图」之间唯一的契约层。
> 前端（小程序）与备用网页渲染器都只读这份 JSON，绝不反向写数。

## 一、生成链路

```
各 00-最新状况.md
  ├─ ## 看板数据       (科目掌握度/知识点/待测)
  └─ ## 任务池候选     (待出任务卡队列)
        │  export_snapshot.py 解析
        ▼
   看板快照 JSON  (snapshot.json)
        │  CloudSync.push_snapshot 推云库
        ▼
   云数据库 snapshot/current  ── getSnapshot 云函数 ──▶ 小程序
                                  drawTask 云函数（抽 task_pool）
```

## 二、快照 JSON 结构

```jsonc
{
  "generated_at": "ISO 时间（本地时区）",
  "data_as_of": "YYYY-MM-DD",
  "evidence_level_note": "🟢真题/🟡样卷/🔴未测 仅后台记录",
  "summary": {
    "subjects_scored_total": 450,
    "mastery_pct": 0.62,                 // 语数英均值（有值才平均）
    "predicted_score_150_each": {"语文": null, "数学": null, "英语": 27},
    "untested_300_note": "中考750中综合/道法/历史/体育等300分待测≠0分",
    "known_future_subjects": ["物理","化学","道法","历史","体育","跨学科"]
  },
  "subjects": [
    {
      "key": "english",
      "name": "英语",
      "status": "active",                 // active | pending
      "mastery_pct": 0.60,                // null = 未测
      "color": "blue",                    // green>0.8 | blue≥0.5 | yellow<0.5 | gray未测
      "weak_count": 4,                    // points 中 status=red/yellow 的计数
      "predicted_score_150": 27,          // null = 待测
      "key_hint": "最该补：完形填空（长语境类）",
      "points": [
        {"point":"完形填空·长语境","mastery_pct":0.20,"status":"red","evidence":"🟢真题"}
      ],
      "untested": ["听力30","口语10","作文20"]
    }
  ],
  "task_pool": {
    "updated_at": "ISO 时间（AI 最近一次重整）",
    "english": [ { "id","type","title","roi","delivered_at","card":{...} } ],
    "math":    [ ... ],
    "chinese": [ ... ]
  }
}
```

- `task_pool.<subject>` 直接以科目 key 为字段（不嵌套 `subjects`）。
- `card` 字段结构复用《06-今日内容交付规范》大字卡：
  - 词/单点型：`word_from / word_to / ipa / collocation / rule / how / why`
  - 考点型（数/语）：`point / rule / how / why`

## 三、Obsidian 端 YAML 契约块

每个学科 `00-最新状况.md` 末尾含两个幂等块（由 `pipeline/init_subject_blocks.py` 初始化）：

### `## 看板数据`
```yaml
subject_key: english
mastery_pct: 0.60
predicted_score_150: 27
weak_count: 4
key_hint: "最该补：完形填空（长语境类，约20%）"
points:
  - point: "完形填空·长语境"
    mastery_pct: 0.20
    status: red
    evidence: "🟢真题"
untested:
  - "听力30"
  - "口语10"
  - "作文20"
```

### `## 任务池候选`
```yaml
- id: en-01
  type: master
  title: "完形填空·长语境逻辑"
  roi: 0.95
  delivered_at: null          # 抽卡云函数 drawTask 回填 ISO 时间
  card:
    title: "完形填空·长语境逻辑"
    rule: "先通读抓主线，再按上下文选词"
    how: "①读首句定主题 ②空前后找线索 ③排除明显错项"
    why: "长语境类是英语当前最大确定性失分面"
```

> 铁律：数字只在 Obsidian 改；改完跑 `export_snapshot.py` 即同步到小程序，不存在第二数据源。

## 四、本地题库 `questionbank.js`（练习用，非数据事实源）

- 位置：小程序根目录 `questionbank.js`（打包进小程序，前端 今日任务 直接 `require` 抽取练习，不依赖云函数）。
- 结构：`questionbank[subjectKey][point] = [ {q, options:[...], answer, explain}, ... ]`，键名与 `snapshot.subjects[].points[].point` 完全一致。
- 生成：由 `pipeline/build_questionbank.py` 生成（词性转换/词汇辨析用种子词表，数家用脚本模板随机生成，完形/阅读用句子级题库）。重跑即覆盖 `questionbank.js`。
- 数量要求：每个考点 ≥ 50 题（实测 53–71 题，共 667 题）。`今日任务` 下拉列出有题库的考点，题量 2–10 随机抽取。
- 说明：题库是**练习材料库**，不属于掌握度数据事实源；掌握度仍以 Obsidian→snapshot 为准。

## 五、考点详细汇报 `reports.js`（AI 维护内容源）

- 位置：小程序根目录 `reports.js`（打包进小程序，前端 `pages/mastery/report` 直接 `require`）。
- 结构：`reports[subjectKey][point] = { summary, score_origin, stats:{total,correct,wrong}, breakdown:[{title,desc,from}], strengths:[...], next_step }`。
- 用途：科目详情页「现阶段掌握内容」里**每一项评分卡可点击** → 进入「考点详细汇报」页，给出：
  1. 📊 评分由来（统计题数/做对/做错/正确率 + 文字解释 % 怎么来的）；
  2. 🔍 具体扣分项（核心失分模式 + 来源哪次作业）；
  3. ✅ 已稳定掌握；
  4. 🎯 提分建议 + 「去练习核心扣分项」按钮（跳今日任务并精确锁定该考点）。
- **维护纪律（用户铁律·AI 持续维护）**：
  - 掌握度数字（mastery_pct/status）**仍以 Obsidian→snapshot 为准**，此处不存数字真相。
  - `stats` 统计题数与 snapshot 的掌握度**保持自洽**（如 20% → 15 题对 3 错 12）。
  - `score_origin / breakdown / next_step` 是 AI 在**每次分析新作业后持续更新**的文字汇报，随新作业迭代；新增考点时在此补一条即可。
  - 语文等暂无作业的科目留空，汇报页会显示「暂无详细汇报」引导语。

## 六、今日任务 · 智能提分练习（核心扣分项优先）

- 进入「今日任务」默认按当前科目列出**核心扣分项**（red/yellow 优先、按掌握度升序），以多选 chips 形式**默认全选**——练习题目即来自这些最该补的扣分项，目的=最大程度提分。
- 顶部科目切换；右侧题量步进器 2–10；「开始练习」从选中的核心扣分项题库随机抽 N 题（点击看答案+解析）。
- 保留「或手动选择其他考点」下拉，作为覆盖全部考点的可选入口。
- 从「详细汇报-去练习」进入时，URL 带 `?subject=&point=`，会精确锁定该考点并自动开始练习。
